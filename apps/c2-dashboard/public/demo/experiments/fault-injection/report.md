# Authority boundaries under injected faults

Experiment `fault-injection`. Generated by `mesh` from `summary.json` and `runs.jsonl`. Every number is measured from recorded simulated runs; no text below was written by a model.

## Research question

Under each injected fault, does the kernel keep every authority invariant, and how much throughput and task progress does the fault cost compared with the same seed and no fault?

## Hypothesis

No fault produces an unsafe commit or a commit without a passing validation. Faults reduce throughput while active and the run recovers after they clear.

Prediction: `unsafe_commits` will not change from `no_faults` to `corrupt_observation`.

## Limitations

- All inputs are simulated. Results describe this simulator and kernel configuration, not people or physical systems.
- Repetitions differ only by seed; they are not independent samples of real-world conditions.
- Mock judges are deterministic rules defined in this repository, not language models.
- Faults are injected by the simulator; real sensor and network failures have other signatures.
- Throughput falls as agents reach their goals, so recovery is compared against the no-fault condition with the same seed.

## Reproduce

```bash
mesh experiment run experiments/fault-injection/manifest.yaml
```

Any single run can be regenerated with `mesh run experiments/fault-injection/manifest.yaml --condition <id> --rep <n>`; its event-log head hash must equal the `head_hash` column of `runs.csv`.
