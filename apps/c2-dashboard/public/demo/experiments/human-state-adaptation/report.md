# Operator-load gating

Experiment `human-state-adaptation`. Generated by `mesh` from `summary.json` and `runs.jsonl`. Every number is measured from recorded simulated runs; no text below was written by a model.

## Research question

When the simulated operator-load index reaches HIGH or CRITICAL, does deferring background proposals reduce the commits the operator must absorb, and what does it cost in background progress?

## Hypothesis

With gating enabled, fewer proposals are committed while load is high, and the load index itself is coupled to the rate of uncommitted proposals.

Prediction: `committed` will decrease from `gating_off` to `gating_on`.

## Configuration

- Scenario: `human-state-perturbation`

## Limitations

- All inputs are simulated. Results describe this simulator and kernel configuration, not people or physical systems.
- Repetitions differ only by seed; they are not independent samples of real-world conditions.
- Mock judges are deterministic rules defined in this repository, not language models.
- The operator-load index is produced by a simulation (operator_load_v1). It is not a measurement of any person and makes no physiological or cognitive claim.

## Reproduce

```bash
mesh experiment run experiments/human-state-adaptation/manifest.yaml
```

Any single run can be regenerated with `mesh run experiments/human-state-adaptation/manifest.yaml --condition <id> --rep <n>`; its event-log head hash must equal the `head_hash` column of `runs.csv`.
