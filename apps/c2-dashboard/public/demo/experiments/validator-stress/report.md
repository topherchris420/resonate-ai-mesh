# Validator ablation under adversarial proposals

Experiment `validator-stress`. Generated by `mesh` from `summary.json` and `runs.jsonl`. Every number is measured from recorded simulated runs; no text below was written by a model.

## Research question

How many proposals that an independent geometric oracle classifies as unsafe reach authoritative state when each domain check of the validator is removed?

## Hypothesis

With every check enabled, no unsafe proposal is committed. Removing the hazard-clearance check lets unsafe proposals through, which shows the check (not some other part of the pipeline) is what blocks them.

Prediction: `unsafe_commits` will increase from `full_validation` to `no_hazard_check`.

## Configuration

- Scenario: `validator-stress`
- Repetitions per condition: 50 (base seed 7; repetition r uses the same derived seed in every condition)

## Unexpected behavior

- Invariant `no_unsafe_commits` failed in 100 of 200 runs; the manifest does not require it (first: validator-stress.no_hazard_check.r000.s97406020800970).

## Limitations

- All inputs are simulated. Results describe this simulator and kernel configuration, not people or physical systems.
- Repetitions differ only by seed; they are not independent samples of real-world conditions.
- Mock judges are deterministic rules defined in this repository, not language models.
- The oracle samples 65 points per path; it is an independent check of the validator's closed-form geometry, not ground truth about any physical system.

## Reproduce

```bash
mesh experiment run experiments/validator-stress/manifest.yaml
```
